# SMR-MIMAR-G 答辩速查

1. **为什么用 full history 而不是 Last-20？** 为刻画稳定长期偏好并避免动态窗口导致的路线抖动；当前实现用全部 rating≥4 正反馈，Last-20 完全不参与 SMR-MIMAR-G。
2. **为什么保留多个 target genres？** 多标签 target 表示多个可达属性，只取一个会丢失迁移方向并引入任意选择。
3. **为什么用数据集共现而非 embedding？** 共现可复现、可解释、无额外模型依赖，并提供 catalog 中确实存在联合标签电影的可行性证据；代价是语义表达较粗。
4. **为什么四条路线？** 冻结工程常量 `ROUTE_SET_SIZE=4`，用于在有限 prompt 预算中覆盖多起点/多目标属性；它不是由本次 evaluator 指标调出的最优值。
5. **为什么五个用户兴趣？** 冻结 `TOP_K_USER_INTERESTS=5`，在多兴趣覆盖和候选规模间取一个简单固定预算；同样未做正式敏感性调参。
6. **为什么路由集静态？** 该版本有意移除动态兴趣、Need/Coverage 与切换状态，隔离并降低动态重排不稳定性。
7. **为什么移除 dynamic interest？** 先前动态方法中结构更新与 rank 效果混杂；SMR 以完整历史的一次性画像建立更易解释的控制方法。
8. **为什么一个 item 可支持多路由？** MovieLens 是多 genre 标签；同一电影可同时满足多个 `(start,target genre)` 的 AND 条件，这正是多属性迁移的交叉点。
9. **为什么 LLM 只选具体 item？** 路由、候选合法性和 metadata 由确定性算法固定；LLM 只在最多 20 个合法标题中作自然下一步选择，减少幻觉和不可审计决策。
10. **为什么 SASRec 不参与 planning？** 避免把 evaluator 泄漏成规划奖励；SASRec 仅后验测 IoI/IoR/Proxy，使规划与评估职责分离。
11. **为什么 TargetOverlap 只作 guard，不作 score？** 先前诊断显示 overlap 大小本身几乎不与 ΔIoR 对齐，但 overlap 下降步骤呈负向风险；因此只阻止结构性后退，不把它优化成排序目标。
12. **为什么 overlap 下降就停止？** 这是最小单调性保护：不重排、不 retry、不引入新奖励；将已选到的后退项排除于路径并直接连接预定义 target。
13. **guard 是否用 evaluator 数据调参？** 实现没有可调阈值：严格条件就是 `O_new<O_prev`。机制动机来自 post-hoc 观察，最终 5-user 结果仍只能视作探索性证据，不能冒充独立验证。
14. **五用户实验的局限？** 样本极小、每用户仅两路径、相同 seed 导致两路径完全重复、单一数据集与单一 4B 模型、合成 target、离线全接受、SASRec token mapping 仅 likely-compatible、无显著性检验。
15. **更大正式实验怎么做？** 预注册冻结代码与超参；扩大并分离开发/验证/测试用户；为重复路径使用预声明独立 seeds；报告均值、方差、置信区间与配对检验；做多模型/多数据集复核；保留无 guard 对照并审计 target、候选池和 mapping；若涉及反馈，使用独立且明示的反馈协议。
